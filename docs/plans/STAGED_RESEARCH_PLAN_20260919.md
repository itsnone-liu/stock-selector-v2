# 策略回测分阶段代码实施方案（Markdown 存档）

> - 统一底座｜分层验证｜低资源运行｜可中途停止
> - 适用仓库：stock-selector-v2
> - 依据版本：2026-09-19 仓库状态（progressive_v1 全量运行后）
> - 原始文件：飞书「策略回测分阶段代码实施方案.docx」（2026-09-19）
> - 本存档为实施依据版本；后续修订递增版本，不覆盖

目标是逐步回答三个问题：中期趋势是否稳定向上；哪种入场方式更优；如何以少赚换取更小的高位回撤。

## 一、方案结论

本轮不应再建设一个不断扩张的全量脚本，也不应每增加一种形态就重建全部历史数据。建议保留当前月线主池和历史行情读取能力，新建一个稳定的核心证据层，再以可插拔的旁路特征表逐步增加周线双轴、回调买点、行情路径、追高研究和退出研究。各阶段只消费自己需要的列，并通过统一的事件编号连接，不相互覆盖。

当前全量分析已经出现明显的资源压力：约 97 万事件行的主面板，全量分析运行约 3 小时 7 分钟，峰值内存约 3.8GB；24 张设计表约 13GB，持有期背景表约 48MB/39 万行（注：原文"4800 万行"为高估，实测 392,648 行）。后续若把回调、行情路径和退出状态直接全部塞进现有流程，内存和磁盘都会迅速扩大。因此本方案把"计算一次、分层复用、按事件聚合、按需求生成"作为工程约束。

建议分为七个阶段。前四个阶段先完成趋势和入场研究；第五阶段才研究 3.5% 涨幅限制；第六阶段研究高位风险与止盈；第七阶段再加入市场和板块背景进行仓位回放。任何阶段都可以停下，前一阶段的文件和代码仍然有效。

| 阶段 | 核心问题 | 主要新增内容 | 是否需要全量重跑 |
|---|---|---|---|
| 阶段零 | 如何保证以后不反复重构 | 数据契约、存储接口、运行清单、资源监控 | 否 |
| 阶段一 | 月线和周线能否识别中期趋势 | 周线结构与周线动能双轴 | 最多一次旁路构建 |
| 阶段二 | 缩量回调和回踩是否是有效买点 | 回调状态和回调事件 | 最多一次旁路构建 |
| 阶段三 | 同一行情中哪种入场方式更好 | 行情事件、路径结果、四种入场回放 | 不重建核心面板 |
| 阶段四 | 当前正向和负向结果差在哪里 | 形态、位置、路径、行业背景分层分析 | 否 |
| 阶段五 | 追高风险值不值得承担 | 涨幅分层和追入等待策略 | 否 |
| 阶段六 | 何时应保守止盈 | 高位分歧、动能衰减、结构破坏 | 一次旁路构建 |
| 阶段七 | 外部环境如何调整仓位 | 市场、板块和 ETF 背景 | 不改个股信号 |

## 二、总体架构

### 2.1 四层数据结构

| 层次 | 保存内容 | 更新条件 | 禁止事项 |
|---|---|---|---|
| 核心证据层 | 股票、日期、月线池状态、原始日周量价、交易日历、规则版本 | 原始数据或基础口径改变 | 不得写入未来收益和实验结论 |
| 状态特征层 | 周线结构、周线动能、日线形态、位置、风险状态 | 对应特征定义改变 | 不得覆盖旧版本字段 |
| 事件路径层 | 行情事件、入场事件、回调事件、退出事件及其阶段 | 事件拼接规则改变 | 不得把每个交易日当成独立行情 |
| 结果分析层 | 未来收益、最大回撤、创新高、策略回放、行业解释 | 观察窗口或分析协议改变 | 不得反向修改信号日特征 |

四层之间统一使用"股票代码+交易日期"连接；行情事件另增加稳定的事件编号。核心证据层一旦冻结，后面的研究只新增旁路表，不向主表无限加列。

### 2.2 推荐目录和模块

| 位置 | 职责 | 实施方式 |
|---|---|---|
| `src/stock_selector/research/panel_store.py` | 统一读取、分批、分区、断点续跑 | 先兼容现有 CSV，后续可切换列式存储而不改分析代码 |
| `src/stock_selector/research/state_axes.py` | 周线拆成趋势结构与当前动能 | 只输出事实和状态，不决定仓位 |
| `src/stock_selector/research/pullback_features.py` | 缩量回调、连续缩量、触线止跌、结构失效 | 独立于上涨触发标签 |
| `src/stock_selector/research/lifecycle.py` | 拼接完整行情的准备/突破/回调/延续/衰减/结束 | 输出事件编号和状态变化 |
| `src/stock_selector/research/entry_replay.py` | 直接追入、等待回调、支撑确认、分批进入 | 只消费事件与价格，不改信号识别 |
| `src/stock_selector/research/exit_replay.py` | 分级减仓、保守退出、延迟退出 | 风险提示与实际卖出规则分离 |
| `scripts/run_research_stage.py` | 统一阶段入口 | 阶段参数选择任务，负责清单、日志和断点 |

### 2.3 版本和依赖清单

每个产物目录必须保存清单文件，至少记录：数据起止日期、股票数量、交易日数量、上游文件指纹、规则版本、配置指纹、代码提交、分批大小、输出行数、峰值内存、运行时间、完成分区和失败分区。上游指纹一致时已完成分区直接复用；状态定义改变时新建版本目录；收益窗口改变时只重算结果层；背景改变时只重算背景旁路表；报告必须写明所消费的各层版本。

## 三、服务器资源控制

| 项目 | 建议目标 | 处理规则 |
|---|---|---|
| 峰值内存 | 默认 ≤2.5GB | 2.2GB 预警；2.5GB 停当前分区并降低批量 |
| 单次分批 | 默认 100 只股票 | 低内存从 50 起步 |
| 并行度 | 默认单进程 | 独立机器或内存确认后才分区并行 |
| 单个中间文件 | ≤2GB | 按年份和代码段分区，禁止 13GB 单体设计表 |
| 持有期背景 | 按事件聚合保存 | 不落盘数千万行逐日明细 |
| 完整运行 | 每阶段最多一次 | 先冒烟和中等样本验收 |

运行阶梯：规则单元测试（人工行情，数秒）→ 人工样例（20-30 只已知股票）→ 冒烟（50 股×3 个月）→ 中等（300 股×1 年，估算全量资源）→ 分区全量构建（断点续跑）→ 轻量汇总（只读必要列）。中等样本推算超预算必须先缩字段，禁止"先跑出来再说"。

存储格式渐进改造：阶段零不为换格式引入大规模依赖；读取接口隐藏文件格式，先支持现有 CSV（分区、列裁剪、分块）；瓶颈证实后再评估列式存储，业务逻辑不改。

## 四、阶段零：统一底座和冻结契约

不新增策略条件，只解决以后如何加功能而不反复重构。代码任务：保留 momentum_panel.py；新增统一存储接口；新增统一阶段入口；产物写独立版本目录+依赖清单；运行资源日志；观察窗口 [1,2,3,5,10,15,20] 写入统一研究协议（30 日仅历史对账单列）。验收（五项）：断点续跑、列裁剪、版本隔离、确定性、资源日志。

## 五、阶段一：月线和周线趋势有效性

周线拆两个独立维度（并行新增，原"允许/观察/排除"字段保留兼容）：

| 维度 | 建议状态 |
|---|---|
| 趋势结构 | 完好、开始受损、破坏、证据不足 |
| 当前动能 | 增强、恢复、健康回调、不明确、减弱、放量下跌 |

星期逻辑：周一用上周与前周完整周，本周首日只增证据；周二保留上涨延续/下跌后恢复/连续下跌但卖压衰减三条路径；周三周四比较已实现周内涨幅、累计成交量、资金效率与历史同进度；周五完整周确认（记录首次与最终确认时间）；节假日短周按真实计划交易日数。输出周线状态旁路表（每股每天一行，只存双轴、星期路径、比较基准、证据完整度和原因）。第一轮分析：月线池全部股票为趋势层总体；比较不同周线结构和动能状态；绝对收益、创新高比例、最大回撤、结构失效比例为主结果；相对行业收益只解释不替代。晋级门槛：代码语义先过人工行情测试；周线双轴无法稳定复现人工判断则不得开始入场研究。

## 六、阶段二：回调和回踩买点

只先定义事实不立即规定仓位。固定 1% 均线距离继续作为原版参照，同时保存真实距离与波动标准化距离。回调事件去重：同一股票从第一次回调到重新创新高/结构破坏/超过最长观察期只形成一个事件；每日状态保留明细旁路表，统计以事件为单位。资源控制：只在月线池内计算；支撑限 10 日/20 日均线和近期平台三类；先输出事件首日/最低点/止跌日/结束日；先算 5/10/20 日核心结果，流程确认后补 1/2/3/15 日。验收：≥30 段行情覆盖健康回调、缓慢阴跌、放量破位、假止跌、支撑后上攻；不一致先修语义，不按收益调阈值。

| 日线状态 | 必要事实 | 暂不预设的结论 |
|---|---|---|
| 缩量回调开始 | 价格回落、成交低于前期、周线结构未破坏 | 不直接认定可以买 |
| 连续缩量回调 | 成交继续下降、未放量破位 | 不因价格继续下跌自动加仓 |
| 触及支撑 | 接近均线、平台或成本参考区 | 接近不等于止跌 |
| 支撑止跌 | 触及后收回、收盘改善或随后确认 | 先作为候选主买点 |
| 回调失败 | 放量跌破支撑、反弹不能收复、周线转负 | 停止加仓进入退出研究 |

## 七、阶段三：行情生命周期和入场回放

行情事件定义：从进入月线多头且周线结构有效开始，到月线退出、周线结构破坏或超最大间隔结束；中间依次记录起爆准备、突破出现、突破确认、健康回调、再次上攻、高位分歧、动能衰减、结构破坏（不必经历全部阶段）。

| 策略 | 入场规则 | 研究目的 |
|---|---|---|
| 直接追入 | 上涨触发收盘或下一可交易时点 | 追高收益和回撤 |
| 等待首次缩量回调 | 健康回调后进入 | 改善成本与错失率 |
| 等待支撑止跌 | 触及支撑并确认后进入 | 稳定性与延迟代价 |
| 分批进入 | 小仓跟踪、回调加仓、确认成主仓 | 贴近实际操作 |

共同结果：实际与扣成本收益；MFE/MAE；创新高比例与所需时间；等待策略成交比例和错失比例；分批策略平均成本、资金占用、最大仓位；趋势对入场错/全错两类失败。计算方式：回放只对行情事件执行；价格路径逐股流式读取，完成即写事件摘要释放内存；逐日明细默认不落盘。

## 八、阶段四：正负结果差异分析

正负结果不按最终收益>0 二分，至少保留四类路径：直接延续、浅回调后创新高、深回调后恢复、突破失败；高位震荡后继续上涨与结束分开。评价顺序固定：先绝对收益与风险路径，再相对行业收益解释来源，最后分析为何没选到同板块更强股票。聚类只描述市场背景（全市场普跌/行业集中下跌/高波动分歧/个股独立失败），不改变准入逻辑、不事后删失败样本；用于仓位只能在阶段七外部验证。

## 九、阶段五：追高和 3.5% 限制

只消费前面已生成的行情事件和路径结果。当日涨幅分层：0-2%/2-3.5%/3.5-5%/5-7%/7%+；记录相当于此前正常波动的倍数、前 5/10/20 日累计涨幅、连续上涨天数、距支撑距离；区分首次突破/中继突破/高位加速；区分板块共振与逆板块。对照：原版限制（>3.5% 不追）、直接追入（取消上限）、小仓跟踪、等待回调、等待支撑确认。结论可能是"趋势足够强时允许小仓追踪，主要仓位等待回调"。

## 十、阶段六：高位风险和止盈

不对称原则：上涨机会需要较强证据，高位风险可以较早响应。

| 风险层级 | 候选证据 | 默认动作候选 |
|---|---|---|
| 高位分歧 | 高换手、放量、宽幅震荡、大涨大跌交替 | 停止追高加仓，减一部分 |
| 动能衰减 | 放量不创新高、冲高回落增多、下跌量大、相对板块转弱 | 继续减仓保护利润 |
| 结构破坏 | 跌破支撑、反弹不能收复、周线明确转负 | 退出剩余仓位 |

三种退出回放：延迟退出（等结构明确破坏）；分级减仓（高位分歧减一部分、动能衰减再减、结构破坏退出，主要候选）；保守退出（首次高位异常大幅降仓）。历史标注与实时特征隔离：未来价格可标注历史结局，当日风险提示只能用当日及以前数据。止盈评价：相对最高浮盈保住多少、机会损失、避免的最大回撤与严重亏损比例、减仓次数/换手成本/重新进入次数、不同背景下的稳定性。

## 十一、阶段七：市场板块背景和仓位

个股信号不变，只验证市场、行业、ETF 资金状态如何调整整体仓位。全市场约 4000 只下跌时池内同步下跌主要是宏观背景，不应解释为体系失效；须单独报告该背景下体系能否相对抗跌、外部仓位控制是否减少实际损失。

## 十二、代码实施顺序和提交边界

每批提交包含测试、样例输出和迁移说明；一个提交只改一层语义。

| 提交批次 | 只做什么 | 明确不做什么 |
|---|---|---|
| 第一批 | 存储接口、阶段入口、清单、资源日志、断点续跑 | 不改策略、不跑全量 |
| 第二批 | 周线双轴及人工测试 | 不增加回调和退出条件 |
| 第三批 | 回调特征和事件去重 | 不进行仓位回放 |
| 第四批 | 行情生命周期与四种入场回放 | 不加入板块仓位 |
| 第五批 | 正负路径分析和追高分层 | 不自动改 3.5% 生产参数 |
| 第六批 | 高位风险与三种退出回放 | 不声称精确识别顶部 |
| 第七批 | 市场板块背景仓位回放 | 不改变个股信号定义 |

## 十三、统一命令接口

```
python scripts/run_research_stage.py \
  --stage weekly-state \
  --start 2024-01-01 --end 2026-09-01 \
  --batch 100 --workers 1 \
  --resume --memory-limit-mb 2500 \
  --out output/research/lifecycle_v1
```

阶段名：base-check、weekly-state、pullback、lifecycle、entry-replay、posneg、chase、exit-replay、context-position。命令只是调度层，业务逻辑在独立模块。

## 十四、每阶段固定报告模板

本阶段研究问题和不研究的问题；输入/输出版本和代码提交；样本生成、去重、缺失处理；绝对收益、中位数、胜率、分布、最大回撤、创新高；相对行业收益及解释；按股票分块和按日期分块的不确定性。

## 十五、阶段一启动清单（第一批之后）

统一存储接口/阶段入口/清单/资源日志就位；周线并行新增趋势结构与当前动能字段；补齐星期路径、节假日短周、双阳效率、连续放量下跌测试；20-30 段人工行情核对；50 股×3 月冒烟；300 股×1 年中等样本估算全量；资源和语义双过后再构建一次全量周线旁路表；先报告能否识别中期趋势再进阶段二。

## 十六、最终判断

研究应从"信号日之后涨不涨"升级为"能否识别一段中期趋势、怎样进入、怎样退出"。工程上先固定数据和事件接口，再按周线趋势、回调买点、行情路径、追高风险、退出风险逐层增加能力。派发与强势换手难区分的问题，不把识别准确率当唯一目标，而是比较不同风险响应速度：提前减仓少赚多少、避免多少深回撤。分级减仓只要在独立时期稳定改善严重亏损和利润回吐，即使不能精确判断顶部也已具有实用价值。

## 附：十二条硬约束

1. 动态月线池按历史时点进出，不用今天的成分回推过去
2. 周线保持与前期比较，周一至周五各自证据口径
3. 趋势结构和当前动能分别保存，健康回调不笼统归入无效观察
4. 上涨触发、回调买点、退出风险是不同通道
5. 同一股票同一段行情形成一个事件，持续信号不重复计数
6. 历史结果标签可用未来数据，实时特征严禁使用未来数据
7. 绝对收益是主评价，相对行业收益只用于解释和选股诊断
8. 聚类只描述市场背景，不直接改变个股信号逻辑

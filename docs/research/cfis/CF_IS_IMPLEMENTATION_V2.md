# CF-IS 实施方案 v2：卖压衰减、四层接力与宏观事件

## 1. 修订依据与最终交付

用户确认：通过数据验证四层资金运动，形成更清晰的介入判断逻辑，再结合可获得数据与宏观形势对未来作判断。用户直觉“宏观事件可能是关键点”作为重点待验假说，不视为已成立事实。

最终交付不是组合频次或行情故事，而是：**当前所处路径、候选介入节点、确认/失效条件、未来路径倾向及置信程度**。研究阶段不自动交易，不修改选股排名与冻结生产系统。

原 Phase 1 盘点保留；原 IS-1 为探索性材料，不是已验证规则。原先“支持退出后能否独立承接”保留为一个问题，但不再作为唯一主问题。

## 2. 核心假说与竞争路径

- H1：无需彻底出清；卖盘及其价格冲击显著下降，加上有效承接，就可能形成底部，早于场外资金大量进入。
- H2：相同起点也可能走向长期低量滞留、指数稳而个股弱或继续破位，原因可能是其他资金需求不足。
- H3（重点）：宏观/政策事件可能是接力转换的催化点，也可能只是短暂脉冲；需要比较事件发生前的资金结构与事件后的反应持续性。
- 竞争解释：普通超跌反弹、市场已有趋势、宏观事件与价格变化共同受其他因素驱动。不能把时间先后直接当因果。

必须同时收录修复成功、长期滞留、再次破位与无事件修复的连续历史，不仅选择著名政策转折点。

## 3. 四层主体与跨层机制

| 研究层 | 研究问题 | 可用证据与限制 |
|---|---|---|
| 国家队/政策性资金 | 是否稳定市场，承接覆盖何处 | 实体披露与政策支持行为代理分栏；ETF 份额不识别真实买方 |
| 大资金（险资、公私募等） | 减仓衰减、观望或股债再配置 | 披露持仓按公开日更新；缺失不制造日流量；险资/固收关联卖压须有证据，不能仅凭两融推断 |
| 个股主力/游资等活跃资本 | 局部吸收与行情组织是否扩散、持续 | episode、板块参与、龙虎榜等行为代理，不擅自指认主体 |
| 散户/跟随资本 | 止损、观望或跟随参与如何变化 | 活跃度、广度、交易结构等代理，不把所有成交等同散户 |

两融是购买力与潜在平仓压力的跨层观测，不是第五类主体。宏观条件与事件作用于各层，不直接进入综合评分。四层主体不能与现有 L1/M/L4/L3 四列组机械等同。

## 4. 数据与程序结构

沿用周表与原始频率，增加旁路研究表，不修改冻结核心表。

1. `weekly_observations`：支持代理、融资变化/速度、成交活跃度、广度/参与/集中、价格冲击与低点结构；每项保留来源、可用时间与缺失。无法直接测卖盘时称卖压代理。
2. `macro_context`：少量低频背景（资金价格/信用环境、股债相对吸引力、经济盈利预期）；发布后更新。修订历史标 `REVISION_CONTAMINATED`，仅作描述背景，不参与强机制结论。
3. `macro_events`：独立事件台账，字段至少为 `event_id, event_type, title, source_url, published_at, first_usable_at, effective_at, event_cluster_id, evidence_status`。区分宣布与生效、事件事实与市场反应。事后预期差不可恢复则留空，不按事后涨跌定义利好/利空。
4. `research_episodes`：压力释放—卖压衰减—承接—接力的连续事件，保存首次可识别时点和状态转移；同一轮行情合并计数。
5. `entry_candidates`：三类候选介入节点及当时依据、缺失、确认/失效条件；仅作研究标记。
6. `outcomes`：未来结果单独存储，绝不回填当期状态。

宏观事件先少量、可追溯地整理权威公开记录；同一政策组合集中发布归同一事件簇，不当多个独立样本。事件日保留日内/日级时间精度：盘后公布不能解释当日收盘，周中事件不能用整周反应假装事件前信息。周表是背景，不是抹去时间顺序的工具。

## 5. 宏观事件的验证设计

先按信息内容建立有限分类：货币/流动性、财政与需求、资本市场稳定政策、外部风险冲击；不预设每类事件一定产生正/负效果。

比较三组：
- 相近跌幅、波动、卖压和支持状态下，有事件 vs 无事件；
- 相同事件类别下，事件前资金结构不同，后续反应是否不同；
- 同样有短期反弹，哪些形成持续扩散，哪些回落或长期滞留。

区分两个时点：
- **事件前判断**：结构是否具备修复条件、仍欠缺什么催化，不预测不可预知的政策日期。
- **事件后判断**：公开事件是否实际带来资金接力；仅事件已知可做候选，反应确认必须等对应数据发布后才能升级。

事件后 1–2 周反应若用作确认，只能从确认时点评估后续表现，不能倒填成事件当天信号。发生后续新冲击记录为新事件或路径变化，不静默删去失败案例。事件研究提供条件关联，不自动升级为政策因果识别。

## 6. 三类候选介入节点（待验证，不是既定买点）

A. **早期平衡**：卖压代理衰减、承接有效、低点趋稳；允许低量，但需区别买卖同时萎缩。
B. **接力启动**：A 之后其他资金参与、板块/个股扩散开始；事件可作为催化证据之一，非必要条件。
C. **修复确认**：推进与广度持续；比较确认收益与追高代价。

分别比较风险、空间和等待成本；不预定哪个最好。市场介入条件与个股结构分开：市场出现候选节点不意味着所有个股可买。

输出形态：观察 / 早期候选 / 接力候选 / 确认 / 失效；阶段命名仅研究用途，不写入生产 CapitalState。

## 7. 结果与验证办法

- 结果：4/8/12 个交易周的真实指数及板块表现、最大不利波动、再创新低、持续推进、等待时间和上涨覆盖；收益代理与官方基准分栏。
- 长期滞留不仅看收益接近零，还看成交活跃度与多数股票状态；指数稳定和个股修复分别判定。
- 先少量开发期连续样本形成规则，再锁定小范围规则看后期留出；不把已看过的全样本包装为未见验证，历史留出受探索污染须披露。
- 重叠窗口按独立事件汇总；不足完整观察窗标为右删失，不当零收益或完整结果。
- 比较价格/广度基础基线、四层结构增量、加入宏观背景/事件的增量；样本不足只给案例证据与方向，不硬报精确概率。
- 所有解释型状态只能用当时可用信息；`available_at >= date` 不是 PIT 验证，通过条件是 `available_at <= assessment_time`。

## 8. 实施批次与停止点

### Phase 2A：数据补齐与小样
核验历史轴生产口径、真实基准、原子可用时间；整理小规模宏观事件台账；构建若干完整连续窗口，含正例、反例和无事件窗口。输出数据缺口与可复现图，不新建全市场采集。

### Phase 2B：路径与候选节点验证
生成事件库与 A/B/C 节点，固定有限定义，比较修复/滞留/破位路径及事件有无差异。输出“支持什么/反对什么/哪些无法判断”与规则草案；此处停止汇报，再由用户决定 Phase 3。

### Phase 3：介入逻辑与工程增量（待授权）
对照 CD-6/CD-7 及价格基线，评估节点风险—空间—等待成本；形成观察、候选、确认、失效判断逻辑。不能仅以样本内收益最高选规则。

### Phase 4：当前研判与可选 Shadow（另行授权）
用最新可用证据与宏观背景形成路径倾向，列后续观察条件与失效条件；有足够验证才报告校准概率，否则给置信等级。无自动交易授权。

## 9. 保留的边界

本修订仅属于 CF-IS，不启动 R6-2，不改变 R6 FundingContext 的描述性上限、不恢复已淘汰 Supply 轴，不推翻 CL-R2 负机制结论，也不把 AVWAP 升级为有效因子。资源仍遵守单进程、峰值内存≤2.5G、流式处理、无整体重建。缺数据降置信度，不以无法绝对证明停止判断。

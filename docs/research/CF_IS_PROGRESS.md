# CF-IS — 资金承接独立性研究进度记录

- **项目代号**：CF-IS（Independent Support / Exit-Absorption / Cost-Band Defense-or-Pressure）
- **状态**：立项记录已建立；研究范围和工程导向已确认；尚未开始数据加工、回放或回测。
- **模式**：Research-Only；不改写 CF-0、CF-1A/1B、CD-0～CD-7、CL 冻结合同，不接入交易权限。
- **目标仓库**：`itsnone-liu/stock-selector-v2`
- **实施方案来源**：用户提供的 `AC独立性研究实施方案_v1.md`，收到于 2026-10-29。

## 1. 项目目标

从一个新的工程观察角度研究四层资金关系：外部/政策支持行为变化时，市场其他层级的参与和承接是否仍能维持，价格结构和成本 proxy 如何反映承压、吸收、破坏与修复。

目标不是证明某个具体机构的因果作用，也不是先建一个高精度预测模型。项目首先要回答：**能否用现有可匹配数据，形成稳定、易解释、对工程监测或后续状态判断有帮助的慢频观察框架。**结果允许支持、反对或无法判断。

## 2. 已确认的用户方向

2026-10-29 用户确认：

- 原方案总体思路成立，核心价值是以新的角度观察四层资金。
- 主要难点是数据匹配，研究应以**慢频**为主。
- 原则上以**工程应用和形成结论/方案**为目标，不应被过度防御性的细枝末节、门禁或契约流程阻塞。
- 先用现有可用数据形成可读的状态图景和工程方案，再按实际发现补足必要数据与定义；避免为了形式完备而无法推进。

执行时应尊重这一路线：先做“够用、可解释、可复现”的工程版本；只保留防止明显错配/时间穿越/身份误归因等必要边界。不把研究扩成长期的契约审查项目。

## 3. 研究边界

- 资金来源身份与可观察行为代理分开。ETF 份额变化只能称为宽基 ETF 份额/申赎行为代理，不直接等同于某个主体买卖。
- 成本带继续称为 `cost_proxy`，不解释成真实机构成本或真实持仓。
- 月/季披露按真实公开时间使用；不得把披露后信息倒填成此前已知状态。
- 当前阶段只做研究分析和工程方案，不修改生产引擎或冻结阈值，不发订单、不分配资本。
- 结论优先描述市场/宽基，其次扩展至板块；不把市场级共享观测伪装成大量独立个股样本。

## 4. 初始数据匹配框架（待 IS-0 用实物数据修正）

采用**周度观察表作为共同工作频率**，而非强求所有字段做严格日频同频联表。原始频率保留在来源表中，聚合到周时记录实际观测日、缺失和披露可用时间，不将月/季披露机械插值为每日状态。

| 研究层次/对象 | 首选现有输入 | 原始频率 | 初步匹配方式 | 解释边界 |
|---|---|---:|---|---|
| L1 政策稳定行为代理 | SSE/SZSE 宽基 ETF 份额、份额变化与 NAV 辅助 | 日，按 T+1 保守可用 | 周内变化、扩张/收缩方向、可用家族覆盖 | 不指认买方身份 |
| L2 长期/机构背景 | 基金报告持仓、可用公开披露；行业/市场背景序列 | 月/季或更慢 | 只在实际披露后更新；作为背景变量/案例注释 | 不制造逐日机构流量 |
| L3 个股主动资本/承接行为 | CD episode、参与度/集中度、CL R3/R4 Effort-Result、cost proxy | 日线为主 | 周度汇总强弱/扩散/吸收/结构变化 | 行为证据不推断具体机构 |
| L4 情绪与跟随资本 | TDX 广度、成交额、涨停等现有情绪轴 | 日→周 | 周内水平、方向与持续性 | 不将价格方向直接作为资金来源 |
| M 杠杆场 | SSE/SZSE 两融余额、流量、去杠杆速度 | 日，按 T+1 保守可用 | 周变动及去杠杆加速/缓和背景 | 不宣称特定主体必然被迫卖出 |
| 结果观察 | 指数/板块/成本 proxy 位置及后续结构 | 周及 5/20 日观察窗 | 先画历史路径、比较背景相近阶段 | 结果不回填进当期输入 |

周频是第一版工程对齐方案，不是先验真理。若某来源的可用性/覆盖明显不匹配，先缩小该维度适用范围或保留为低频注释，不因一个字段不齐而阻塞整个研究。

## 5. 分阶段进度

### Phase 0 — 立项与方向冻结（完成）

- 接收并阅读用户提供的 v1 实施方案。
- 确认 Research-Only 与不改冻结主线的边界。
- 用户确认慢频、数据匹配优先、工程应用导向；确立周频为初始共同观察尺度。
- 建立本进度文件。

### Phase 1 — 现有数据实物盘点与周频可匹配性（待开始）

目标：用有限时间回答“能用什么、能对齐到什么程度、先做哪张图/哪张表”。

- 只读检查已有 ETF 份额、两融、市场广度/成交额、CD 板块/episode、CL Effort-Result/开盘结构、成本 proxy 数据。
- 重点统计每项：日期覆盖、实际粒度、市场/板块/个股适用层级、可用时间口径、缺失/重复大致情况及可联表键。
- 先构造一张**小规模周频样表**（例如共同覆盖年份的一段连续窗口），用它验证日期与层级如何匹配；不要求先处理全量历史。
- 产物建议：`docs/research/cfis/IS0_DATA_MATCHING.md`、简要机器可读字段表、1 张周频样表/示意图。
- 明确停止点：盘点和小样拼接完成后，给出可执行的 v0 数据方案与已知缺口；不因非核心数据缺失扩大为长时间审计。

### Phase 2 — 慢频描述性历史图景（IS-1/2，待 Phase 1 之后）

- 将各层输入按周组织为并列观察轴，先保留原始量和方向描述，不先做总分或黑箱综合指数。
- 选若干有代表性的市场阶段进行图表和案例整理，同时用一段连续全规则窗口检查观察是否只是故事挑选。
- 可以试做轻量标签，例如“支持代理偏强/减弱 × 承接广/弱/混合”；标签用于叙述与汇总，不进入 CF 当前生产原子/Capital Weather。
- 重点回答状态何时分化、何时同向、哪些组合常见、哪些输入根本无法匹配。

### Phase 3 — 工程价值检查与简洁结论（IS-3，待 Phase 2 之后）

- 比较已有 CD-6 市场权限、CD-7 入场成本区等工程基线之上，CF-IS 观察是否提供额外的风险解释或监测价值。
- 先采用可解释的结果统计/案例对照与少量时间留出；避免多轮阈值搜索、复杂因果表述和以收益最优为目标。
- 结果有增量：提出最小、可选、研究状态到工程接口的建议，由用户决定是否进入后续 Shadow。
- 结果无增量或数据不足：如实说明适用范围，保留为研究看板/背景监控或停止；不以复杂化挽救。

### Phase 4 — 可选 Shadow（暂不启动）

只有 Phase 3 显示稳定工程价值且用户明确批准，才讨论低频、只记录、不下单的 Shadow。当前没有生产接口变更授权。

## 6. 精简质量原则

保留三项必要质量保障，而不建立重型门禁流程：

1. 关键输入按真实可用时间匹配；若时间口径不清，标记不确定并缩小结论，不伪装精确。
2. 对数据匹配、聚合及描述标签保留可复现记录，以便修正和重算。
3. 结论区分观察、解释和假说；代理数据不能越界写成真实身份或因果事实。

除此之外，采用渐进式质量控制：先做小样、看图、找问题；只在会改变结论的关键点上补严谨性。

## 7. 明确不做

- 不先对全仓库每个字段进行无止境的 authority/PIT 全量审计。
- 不等所有资金层披露频率一致后才启动；低频信息按其自身频率使用。
- 不把每天每只股票扩成虚假的独立样本，不用行数替代独立市场阶段数量。
- 不为满足形式预注册而写庞大复合状态合同；先并列数据和初步规则，确认可读且有用后再冻结小范围规则。
- 不做全市场新数据抓取、不做真实交易、不改冻结系统。
